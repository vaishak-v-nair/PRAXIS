WHAT SETUP DOES

Keep your reviews.

Private app runtime
Installs locked frontend dependencies and prepares Python with a checksum-pinned official Astral uv download. No administrator access or global Python changes.
Persistent local data
Saved reviews and provider settings stay outside npm's cache and app release folders. Existing project evidence, keys and memory are never imported automatically.
Healthy startup
Opens the local interface only after the actual API and page respond. Ports already used by another service are reported; that service is left running.
AFTER STARTUP

Review, understand, decide.

  1. Bring your project. Select a local path, GitHub repository URL or folder upload in the local app.
  2. Start with a source review. Describe what the project should do. The default review needs no Docker or model key and executes no project commands. Copy the resulting brief to your coding agent.
  3. Add AI review when needed. Configure your provider and shared spending limit in the app. Optional model review sends bounded, redacted excerpts; setup itself makes no paid calls.
  4. Choose how deeper checks run. Explicitly authorize trusted local execution, or use Docker in Linux mode for container execution. Local checks retain your computer's file and network permissions; a review copy is not an OS sandbox. Missing Docker never triggers a local fallback.
  5. Review the plan before changing source. Draft a fix plan locally, then choose a model handoff or copy it to your coding agent. Source changes require their own approval and fresh verification.

This is a local web application, not a signed desktop installer. Node.js is still a prerequisite. The hosted browser trial inspects source only and does not run your project.
