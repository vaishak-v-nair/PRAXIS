The recording is the original offline receipt demo, not a verdict about your project. A valid signature protects a record's integrity; it does not prove that every user journey works. Workbench review records stay separate.

Project memory

Keep the reasons behind the code.

Local markdown memory preserves decisions, constraints, attempted approaches, and session summaries, so the next coding session has useful context to read.

Supported Claude Code hooks capture locally and CLAUDE.md links the file into later sessions. Other agents can read the portable file; automatic capture depends on supported client formats. Memory is gitignored by default.

Before the next change. After the check.

When “done” is the only evidence

  • A plausible diff can hide a missing side effect.
  • A passing test may never touch the changed path.
  • The next agent receives a vague request to “fix it.”
  • Project decisions disappear between sessions.

With a PRAXIS review

  • Source findings cite where to investigate.
  • Executed checks and missing evidence stay separate.
  • A copyable brief gives an agent a grounded next step.
  • Local memory preserves important decisions.
Your choices, in view

Useful evidence. Clear boundaries.

i.

Source stays close

The browser trial analyzes selected files in memory without uploading the project. Local reviews keep a separate copy on your computer. GitHub intake and optional advisory checks use the network.

ii.

Models are optional

Source inspection needs no key. Opt-in model review sends bounded, redacted excerpts to your configured provider under a shared spending limit.

iii.

Execution is a choice

Authorize trusted host checks or choose Docker. Host checks retain this computer's file and network permissions; failed Docker setup never switches to host execution automatically.

iv.

You approve changes

A brief is a handoff, not an edit. Local source apply retains confirmation, freshness checks, backups, and rollback. GitHub and folder reviews can export proposed changes.

The flight recorder

Git records what changed. Praxis records why.

npx praxis-memory trace reads supported session context from plain Git notes: what was asked, what changed, and the agent's own closing account. That account is testimony, not an independently verified outcome.

Notes stay local until you deliberately share them with git push origin refs/notes/praxis. Existing Git hooks remain intact.

Questions

Straight answers before you start.

Do I need Docker?

No. The default local review inspects source without running the project. Deeper checks are optional: authorize a trusted host run or choose Docker for container execution. Host checks retain your computer's file and network permissions.

What can the browser test prove?

It inspects selected source files in browser memory and gives findings with file references and a copyable brief. It does not install dependencies, run tests, observe user journeys, or certify production readiness.

Does my project leave my computer?

The browser trial sends no project upload; it downloads its analysis runtime and engine. Local review keeps a separate copy on your computer. Optional model review sends bounded, redacted excerpts to configured providers. GitHub intake and advisory checks use the network.

What do I need to install locally?

Node.js 22 or later. The managed launcher prepares a private Python runtime and locked app dependencies without a separate Git or Python installation. Initial setup needs downloads. The local setup page checks the exact npm release before showing its public command; a source-checkout route is also available.

Do I need an AI provider key?

Not for source inspection or the assembled agent brief. Optional model review and fix planning require configured provider access, use a shared spending limit, and may incur charges. A configured key does not prove remaining credit.

Will PRAXIS fix my project automatically?

The browser trial gives findings and a brief. Locally, you can draft a plan, review it, and choose a model handoff or your existing agent. Editing and applying changes need separate authorization. A finished plan is not an implemented fix.

Can builders, developers, and teams use the same workflow?

Yes. Each can inspect source findings, see missing evidence, and decide the next action. Portable briefs can be shared deliberately. The browser trial is not a hosted team workspace.

Are memory, receipts, and the mascot still included?

Yes. The existing CLI, hooks, supported receipt formats, MCP tools, and Windows tray remain available. A valid receipt signature checks the record's integrity; it does not establish that every behavior is correct.
