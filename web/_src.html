What is Praxis?

A memory layer for your AI pair-programmer.

Claude Code is brilliant for a session, then forgets everything when it closes. Praxis fixes that. It is a small open-source tool that distills each coding session into durable project memory — the decisions, constraints and reasons — and hands it back to Claude automatically the next time you open your project.

$ the CLI

One command sets up the hooks. npx praxis-memory and the loop is running — nothing else to configure.

✎ the memory file

.praxis/memory.md — plain markdown in your repo. Redacted, size-capped, readable by any tool or teammate.

◉ the companion

praxis status — the axolotl as a status bar for session health. A desktop tray build is next on the roadmap.

What it keeps

Not a log. The reasons.

Praxis maintains one durable markdown file holding the truth of your project: the architectural decisions, the constraints, the dead ends already explored, and the load-bearing weirdness a fresh session would otherwise delete.

Written automatically when a session ends. Read back automatically when the next one opens. Owned by you, readable by anything.

.praxis / memory.md — written automatically
## Project
Acme API · Fastify + Postgres.
Auth: short-lived JWT. cache.ts memoizes claims —

- tried a Redis lock (reverted: overkill)
Why it matters

Your mornings, before and after.

  • Twenty minutes of warm-up prompts before real work.
  • It "simplifies" the one file that must never be touched.
  • Yesterday's dead ends get re-explored today.

With Praxis

Design principles

Memory that stays on your machine.

i.

Local by design

The entire capture loop runs beside your code. No server, no telemetry, no account — nothing is uploaded, ever.

ii.

Zero added cost

Praxis rides the Claude Code subscription you already run. It makes no API calls of its own and adds nothing to your bill.

iii.

Owned by the repo

Memory lives in your project, gitignored by default. Commit it to share context with your team, or keep it private.

iv.

Self-loading

CLAUDE.md includes the memory file, so every new session reads it without being asked. No paste, no prompt engineering.

How it works

The memory survives the session.

01

Session ends

You close Claude Code. Context would normally vanish here.

02

Stop hook fires

A Claude Code Stop hook runs — locally, on your machine.

03

Decisions written

The session's durable decisions land in .praxis/memory.md — redacted and size-capped.

04

CLAUDE.md links it

The memory file is included from your project's context file.

05

Next session recalls

Claude reads it on open. No paste, no re-explaining, no lost week.

An axolotl can regrow a lost limb. Praxis regrows lost context — the same loop, every day, without you thinking about it.

Questions

Everything people ask first.

Does my code ever leave my machine?

No. Praxis is local-first by construction: the capture hook, the memory file, and the tray app all run on your machine. There is no server to send anything to, no account to create, and no telemetry. The memory is a plain file in your repository.

What exactly does it remember?

Durable decisions, not transcripts — the architecture you settled on, the constraints you discovered, the approaches you tried and reverted, and the reasons behind them. That is the context a fresh session loses and a transcript buries.

How is this different from maintaining CLAUDE.md by hand?

Praxis maintains the memory automatically. A Claude Code Stop hook distills each session's decisions into .praxis/memory.md, keeps it redacted and size-capped, and links it from CLAUDE.md so it loads on every open. Hand-written notes rot; the loop doesn't.

What does it cost to run?

Nothing beyond what you already pay. Praxis makes no API calls of its own — it rides the Claude Code session you're already running, so there is no subscription, no metered usage, and no second bill.

Can my team share the memory?

Yes. The memory file is gitignored by default, but committing it turns project memory into shared team context — every teammate's Claude opens with the same knowledge of the codebase and its history.

Which tools does it work with?

Claude Code today. Because the memory is one portable markdown file, it is readable by any editor, agent, or AI coding assistant — support for more tools is planned, and the format will stay plain markdown.

Does it work on Windows, macOS and Linux?

Yes — the same single command everywhere: npx praxis-memory. The only requirement is Node 18+, which Claude Code itself already needs, so if Claude runs on your machine, Praxis does too.

I typed / and don't see the Praxis commands

Three usual causes. Run the setup first (npx praxis-memory in your project). If a Claude Code session was already open during setup, restart it — the / menu loads at session start. And setup installs the commands both in the project and user-wide (~/.claude/commands), so after one setup they appear in every project.

Is the tray app available now?

The companion ships in the CLI today — praxis status reports session health and what the memory holds. The desktop tray version shown above is the design it's growing into, next on the roadmap after v0.1.
