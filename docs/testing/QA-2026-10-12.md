# PRAXIS quality assessment — 2026-10-12

## Decision

**NO-GO for an unqualified public production-readiness claim.** The tested local
review path, installed CLI, and public browser trial work on the fixtures below.
Provider quality/credit, official external evidence servers, packaged desktop
installers, real customer repositories, and broad-load behavior were not
established. The large-checkout self-review was explicitly limited.

PRAXIS is a local-first project review system: a dependency-free CLI in `src`;
a Next.js Workbench connected through a loopback gateway to a Python FastAPI
engine and SQLite; a static public website with an in-browser source trial; and
an optional desktop shell. Source inspection, model analysis, project execution,
agent completion, and signed Verify receipts are separate outcomes.

## Reproduced defects and repairs

**QA-01 — High — implicit model call through scan API.** POST
`/api/scans` with only a local `source`. Expected: the documented default
source-only review, without model spend. Before repair: the API's default
`ai_review=True` invoked the provider path; a new regression failed because
`provider.analyze` was called. The model option and worker fallback now
default to false. Intentional AI-review tests explicitly pass `ai_review=True`.
The focused 45-test API suite, final backend suite, and live production-gateway
request passed; the live job completed at cost 0 with AI coverage marked skipped.

**QA-02 — Medium — misspelled scan options silently accepted.** POST with
`ai_revew` or `run_check` previously returned HTTP 200 and created jobs
without performing the requested work. Expected: invalid input rejected before
work. `ScanInput` now forbids extra fields. The regression failed before the
change and passed afterward; a live production-gateway request returned 422.

**QA-03 — High — vulnerable Workbench dependency.** The pinned Next.js
16.3.6 produced a high-severity `npm audit` result. Updated the exact
Workbench package and lockfile to 16.4.0. Workbench audit now reports zero
vulnerabilities; TypeScript, optimized build, rendered assurance, and browser
accessibility checks passed after the update. The [Next.js 16.4 release](https://nextjs.org/blog/next-16-4)
and [GitHub advisory](https://github.com/advisories/GHSA-3w37-wq28-93x7)
provide upstream context; local audit results are the direct dependency evidence.

**QA-04 — Low — live trial test coupled to copy and visibility.** The first
Vercel run timed out waiting for an exact old headline. The deployed trial
still navigated correctly and had no browser errors. Cloudflare rendered the
folder input hidden behind a picker, which also broke a visibility-only locator.
The test now waits for the input to be attached, checks that there is one main
heading, and continues to exercise the real folder scan. The corrected suite
passed on localhost, Vercel, and Cloudflare.

## State, performance, and remaining risk

- A source-only job remained complete after a production-app restart. On its
  one-project local fixture, 20 sequential workspace GETs had a 10.3 ms median,
  22.5 ms p95, and 27.4 ms maximum. This does not predict concurrent-user
  throughput or large-project latency.
- A bounded, non-executing self-review of this checkout took 99.81 seconds.
  It inspected 2,026 eligible files, omitted 8,846 under snapshot limits,
  excluded four nested repositories, and correctly labeled source inspection
  **limited** and readiness **blocked**. Its 68 findings are scanner hypotheses,
  not 68 independently confirmed defects. Original source was unchanged.
- The full root development-dependency audit still reports three high entries
  along the Promptfoo → jks-js → node-forge chain. The
  [node-forge advisory](https://github.com/advisories/GHSA-86w9-cpqp-85rv)
  lists no patched version. This dependency is not in the zero-dependency
  shipped CLI; forcing a breaking Promptfoo downgrade was not an evidenced fix.
- The deployed Vercel and Cloudflare trial HTML matched each other (SHA-256
  `7DF5F5DFB6E3A6CEE981746D25682AED0A78E5F6B77FB9D995DA1954DCBE277D`)
  but differed from this checkout's trial HTML
  (`CA8D48E4039848DC5BA8F72B6449767C6287029A50FBBCAB1FD02238597FEA66`).
  Both deployed user journeys passed. Deployment provenance should be reconciled
  before claiming that this exact checkout is public.
- Live provider credits/quality, GitHub clone with varied credentials/network
  failures, vendor MCP accounts, Docker execution in this run, macOS/Linux
  desktop installers, hostile multi-tenant access, payments, and sustained load
  were unverified. The public site is a browser-memory source trial, not the
  local Workbench or a hosted marketplace.
